# 脚本注释与桌宠重构计划

## 已确认的注释规范

- 范围：`Assets/Script` 下的项目脚本，排除第三方插件和生成代码。保持 UTF-8 编码，遵循 `.editorconfig`。
- 使用成对的 `#region` / `#endregion` 按功能划分；不再使用长横线分隔注释，不为每个方法单独建立区域。
- 类说明采用多行 XML 文档：第一行写中文类名，第二行以 `- ` 开头说明精炼职责。
- 每个方法（含生命周期、私有方法和协程）均有 `<summary>`；参数逐一填写 `<param name="实际参数名">`；非 void 返回值填写标准 `<returns>`，协程说明其迭代器所控制的流程。
- 文档确需分段时使用 `<para>`；需要简单换行时可用 `<br/>`。泛型参数使用 `<typeparam>`。
- Inspector 可编辑字段使用 `[Tooltip]` 说明用途、单位或约束；私有运行状态及其他重要成员使用单行 XML `<summary>`。
- 方法内部保留有价值的 `//`，解释关键分支和约束，避免逐句翻译代码。说明统一使用简体中文，标识符保持原样。
- 先核实逻辑再写注释，不把当前实现没有提供的能力描述成保证。注释整理不改变方法签名、序列化字段、数值、调用次序或游戏逻辑。

- 补充：Tooltip 仅用于实际参与 Inspector 序列化显示的字段，包括受支持的 public 实例字段及显式序列化字段；不用于属性、静态/常量/只读字段、未序列化私有缓存或不显示的字段。不为了添加 Tooltip 而改变字段访问级别或序列化方式。当前 RandomEvent 只由未序列化的私有列表持有，其内部字段使用 XML 说明。

## 对象池与Addressables统一管理阶段（2026-09-15）

- 新增 `AddressableManager`，统一提供按地址加载、Result/Handle缓存、同键并发请求合并、Label资源预加载及句柄释放能力。
- `AudioManager` 不再自行维护Addressables加载句柄和音频缓存，改为调用统一管理器；音频组的全部资源统一增加 `Audio` Label，管理器创建后会自动预加载该标签。
- 新增 `ObjectPoolManager`，按预制体维护闲置实例队列，提供获取、归还、延迟归还和对象主动归还接口。
- 伤害、恢复和增益飘字统一接入对象池；`TMP_Figure` 改为在 `OnEnable` 重置生命周期和透明度，超时后优先归还对象池，未进入对象池时保留销毁兜底。
- 暂不池化敌人、炸弹和带复杂协程/物理状态的玩法对象，待补齐统一的重置协议后再迁移，避免改变现有行为时序。

## 与毕设项目架构对齐的后续优化计划（2026-09-19）

对比《Dweller of the Fading Stars》毕设项目后确认的下一批优化方向。当前均为计划，尚未实施；实施时沿用既有验证纪律：分阶段提交、可单独回退、排除属性后的代码语法标记对比、数值断言与 Bee/Roslyn 编译验证、Play Mode 回归清单。

### 阶段与优先级

| 阶段 | 内容 | 优先级 |
| --- | --- | --- |
| A | 难度配置数据化 | 最高，成本最低 |
| F | 地图数据化（MapConfig + Map Prefab） | 高，为多地图与随机生成铺路 |
| B | `IDamageable` + `DamageInfo` 统一伤害入口 | 高，对象池重置协议的前置条件 |
| C | 食物效果配置化 | 中，内容扩展加速器 |
| D | 轻量 Buff 聚合 | 可选，需食物叠加玩法时实施 |
| E | 表现层事件化 | 与 D 配合实施 |

### 阶段A：难度配置数据化

- 参考毕设项目 `MonsterConfig` 的 ScriptableObject 模式，新建 `GameDifficultyConfig`：桌宠生命、无敌时间、恢复倍率、敌人生命倍率、生成时间修正、攻击基础伤害与冷却。
- `GameDifficultySystem` 持有当前难度配置并对外分发。
- 删除 `VpetHealthSystem`、`EnemyHealthSystem`、`SpawnPoint` 等处的 `switch (GameDifficultySystem.Instance.CurrentDifficulty)` 数值分支，改为读取配置字段。
- 边界：只迁移常量归属，不改变任何数值与生效时机；迁移前后逐项数值断言对齐。

### 阶段B：IDamageable 与 DamageInfo 统一伤害入口

- 参考毕设项目 `10-Mob/IDamage` 模式，定义 `IDamageable` 接口与 `DamageInfo` 结构体（数值、来源类型、命中点、方向）。
- `VpetHealthSystem`、`EnemyHealthSystem`、`Item_Block` 的受伤入口统一为 `TakeDamage(DamageInfo)`；普通攻击、舞蹈范围攻击、炸弹、尖刺、石锥全部改走同一接口。
- 敲击方向与击退力随 `DamageInfo` 传递，移除各攻击方自行施加的重复外力逻辑。
- 边界：本阶段是文档已记录的"统一重置协议"雏形，完成后才评估敌人、炸弹接入 `ObjectPoolManager` 的可行性；保留旧入口方法签名作过渡，逐步收拢调用方。

### 阶段C：食物效果配置化

- 参考 `06-Prop/PropEffect` 模式，为 `ItemData` 增加效果配置子资产（如 `FoodEffectConfig`）：恢复量、增益类型、时长、触发随机事件的权重表。
- `VpetState_Eat` 的 `switch (item.itemID)`（case 0~5）与 `switch (eventIndex)`（case 1~7）、`DragController` 的 `itemID <= 49` / `== 50` 魔法编号判断改为按配置驱动。
- 边界：保留现有 itemID 枚举与旧资源兼容，新配置存在时优先；不改变现有食物的实际效果数值。

### 阶段D：轻量 Buff 聚合

- 参考毕设项目 `CharacterBuff` 的聚合思想但做最小化：`List<BuffInstance>`、按类型加法/乘法聚合、到期清理，不引入堆叠合并与脏缓存机制。
- 聚合对象覆盖现有临时效果：攻击伤害倍率、冷却倍率、加速、无敌、一拳、恢复倍率；对外仅暴露按类型查询与 `OnStatChanged` 事件。
- `VpetAttack.SetTemporaryModifiers` 与 `VpetEffect` 的限时增益改为读写聚合结果，消除多计时器互相覆盖的可能。
- 边界：不新增玩法，仅收敛现有效果的存储与计算路径；效果时长与数值保持不变。

### 阶段E：表现层事件化

- 生命系统发出 `OnHealthChanged(current, max)` 事件；血条、头像组件订阅刷新，删除 `VpetHealthSystem.Update()` 的每帧同步。
- 血条与头像表现逻辑迁入规划中的 `VpetPresentation`（后续整理为 `VpetAnimation`）。
- `MapProgressBar` 的每帧进度计算改为位置变化阈值触发或事件驱动。
- 顺带补全 `VpetState_Idle` 占位处理器为真正的待机行为，完成状态机最后的历史欠账。
- 边界：表现层重构不改变结算、重生与难度判定时机。

### 阶段F：地图数据化

- 参考毕设项目 `MapConfig` / `MapMonsterConfig` 模式，将现有地图抽象为 Map Prefab + `MapConfig`（ScriptableObject）。
- `MapConfig` 承载：进度起点/终点 X、检查点列表、出生与胜利位置、BGM、主题引用；`MapProgressBar` 删除 -14/550 与固定 2 个检查点的硬编码。
- 场景仅保留游戏外壳（GameManager、UI、桌宠），通过现有 `AddressableManager` 或 Instantiate 加载地图 Prefab；敌人 `SpawnPoint` 作为地图 Prefab 子对象随地图分发。
- 边界：与"Tilemap 地图/随机生成关卡"评估结论一致，Tilemap 渲染与碰撞方案保持不变；本阶段只完成数据组织迁移，不实现随机生成。

### 实施顺序与依赖

- A、F 相互独立，可先行；B 的伤害入口是敌人/炸弹对象池迁移的前置；C 依赖 ItemData 结构稳定；D、E 建议合并为一个阶段实施。
- 每阶段完成时在本文件追加实施记录与验证结果，格式沿用既有条目。
